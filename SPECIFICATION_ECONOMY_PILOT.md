# Specification-Economy Pilot

This pilot is deliberately limited.

It compares a canonical explicit product encoding with the Operativity pattern on a small task corpus by counting syntactic obligations/atoms.

It does **not** measure:
- human comprehension;
- authoring time;
- error rate;
- expert preference;
- superiority over optimized HyperLTL/LTL encodings.

Therefore any reduction found here is only evidence that the pattern factors out repeated product-state boilerplate under this chosen canonical encoding.

## Why run it?

A specification pattern is expected to reduce repeated low-level formalization. The pilot checks whether that basic compression exists before investing in an external benchmark translation or controlled user study.

## Q1 gate

A positive pilot is necessary but not sufficient.

Strong evidence would require external tasks and either:
1. comparison with expert-written conventional specifications, or
2. a controlled study measuring correctness/time/usability.
